============================================================
BIN IA ASISTEM
VERSIÓN 1.8
ESTADO ACTUAL DEL DESARROLLO
============================================================

BIN V1.8 representa la primera versión que considero suficientemente
estable y funcional para comenzar a utilizar el sistema en automatizaciones
reales de uso cotidiano.

Esta versión todavía no representa el objetivo final de BIN.

Su propósito actual es ofrecer una base funcional de automatización
inteligente en Windows, combinando:

- Automatización determinista mediante Python.
- Control de mouse y teclado.
- Interacción con aplicaciones de Windows.
- Grabación de demostraciones realizadas por el usuario.
- Interpretación semántica de las acciones grabadas.
- Ejecución de tareas programadas.
- Análisis visual del escritorio.
- Razonamiento mediante Qwen3-VL.
- Recuperación básica ante cambios en la interfaz.
- Ejecución de herramientas y comandos desarrollados específicamente
  para ampliar las capacidades de BIN.

La filosofía actual de BIN consiste en que la IA no controle directamente
el sistema operativo.

Qwen analiza la situación, determina qué debería hacerse y solicita una
acción.

BIN se encarga de ejecutar físicamente esa acción mediante herramientas
deterministas de Windows, Python, Win32, pynput y otros mecanismos locales.

Después de ejecutar la acción, BIN puede volver a observar el sistema y
permitir que Qwen determine el siguiente paso.

============================================================
VISIÓN DE BIN
============================================================

BIN puede realizar capturas del monitor y entregarlas a Qwen para analizar
el estado visual del sistema.

Actualmente, antes de enviar una captura a Qwen, BIN reduce la imagen a
una resolución máxima de:

640 x 360 píxeles

El escalado conserva la relación de aspecto de la pantalla, por lo que la
imagen final puede tener una resolución inferior dependiendo de las
proporciones del monitor.

Esta resolución es intencional.

Aumentar significativamente la resolución permitiría a Qwen distinguir
elementos visuales más pequeños, pero también aumentaría de forma
considerable:

- El tiempo de respuesta.
- El procesamiento requerido.
- El consumo de contexto/tokens visuales.
- El uso de memoria.
- El tiempo necesario para que Qwen analice cada captura.
- El tiempo total de ejecución de una automatización.

Por este motivo, V1.8 mantiene temporalmente una resolución visual máxima
de 640 x 360.

Como consecuencia, BIN puede tener dificultades para distinguir elementos
pequeños directamente en el escritorio, especialmente:

- Iconos pequeños.
- Textos pequeños.
- Elementos visuales muy juntos.
- Accesos directos del escritorio.
- Interfaces con muchos controles pequeños.

Durante esta versión se priorizará complementar la visión de BIN mediante
software auxiliar, herramientas deterministas y comandos extraordinarios
desarrollados por el usuario.

La intención es que estas herramientas realicen operaciones concretas y
BIN/Qwen las supervise, seleccione o coordine de manera inteligente.

De esta forma es posible mantener tiempos de respuesta razonables sin
depender exclusivamente de una resolución visual más alta.


============================================================
CAPACIDADES ACTUALES
============================================================

1. APERTURA DE PROGRAMAS
------------------------------------------------------------

BIN puede abrir correctamente aplicaciones que Windows puede resolver de
forma directa o cuya ruta/ejecutable puede identificar.

Actualmente funciona correctamente con aplicaciones como:

- Bloc de notas.
- Microsoft Word.
- Microsoft Excel.
- Aplicaciones y herramientas estándar de Windows.

Sin embargo, todavía tiene dificultades para abrir determinadas
aplicaciones que requieren mecanismos de lanzamiento diferentes,
integraciones especiales, aplicaciones de Microsoft Store o rutas que
Windows no resuelve fácilmente.

Ejemplos donde actualmente puede presentar dificultades:

- Netflix.
- AutoCAD.
- Algunas aplicaciones instaladas mediante Microsoft Store.
- Determinados programas de terceros.
- Aplicaciones que aparecen en el buscador de Windows, pero cuya ruta de
  ejecución BIN no consigue resolver correctamente.

La apertura universal de aplicaciones sigue siendo una capacidad pendiente
de mejorar.


2. ANÁLISIS DE SISTEMAS E INFORMACIÓN
------------------------------------------------------------

BIN puede analizar sistemas y situaciones de complejidad moderada.

Puede observar información, procesarla mediante Qwen y producir un análisis
escrito.

También puede escribir ese análisis automáticamente dentro de un documento,
siempre que la operación y el contenido no sean excesivamente extensos.

Actualmente esta capacidad funciona mejor con:

- Análisis cortos.
- Resúmenes.
- Interpretaciones de información.
- Comparaciones.
- Descripciones.
- Textos de longitud moderada.

Los procesos que requieren mantener cantidades muy grandes de información
durante muchas iteraciones todavía pueden superar las capacidades prácticas
de esta versión.


3. ESCRITURA AUTOMATIZADA EN DOCUMENTOS
------------------------------------------------------------

BIN puede escribir texto automáticamente dentro de documentos y
aplicaciones compatibles.

Esto permite utilizarlo para:

- Redactar información.
- Crear documentos.
- Introducir análisis.
- Escribir instrucciones.
- Completar determinados campos.
- Automatizar contenido generado previamente por Qwen.


4. GENERACIÓN Y ANÁLISIS DE CÓDIGO
------------------------------------------------------------

Qwen puede:

- Generar código.
- Analizar código.
- Detectar determinados problemas.
- Proponer modificaciones.
- Explicar código.
- Crear fragmentos y estructuras de programación.

Sin embargo, V1.8 todavía no dispone de un flujo suficientemente robusto
para:

Generar código → abrir automáticamente el archivo correcto → modificarlo
de manera segura → guardarlo → comprobar que quedó correctamente escrito.

Por este motivo, aunque BIN puede generar y analizar código, todavía no
se considera capaz de escribir automáticamente código en archivos de
desarrollo y guardarlos de forma totalmente autónoma y confiable.

Esta capacidad queda pendiente para versiones futuras.


5. COMANDOS DEL SISTEMA OPERATIVO
------------------------------------------------------------

BIN puede ejecutar diferentes comandos del sistema operativo.

También puede ejecutar herramientas y comandos extraordinarios creados
específicamente por el usuario.

Esta será una parte importante del funcionamiento de V1.8.

La intención es crear pequeñas herramientas especializadas para operaciones
que resulten difíciles, lentas o poco confiables mediante visión.

Qwen podrá decidir cuándo utilizar esas herramientas y BIN se encargará de
ejecutarlas.

Esto permitirá construir automatizaciones híbridas:

IA para decidir.

Python/Windows para ejecutar.

Herramientas especializadas para resolver operaciones complejas.

Qwen para supervisar el resultado.


============================================================
DEMOSTRACIONES Y APRENDIZAJE DE TAREAS
============================================================

BIN permite al usuario mostrar una rutina utilizando normalmente el mouse
y el teclado.

Durante una demostración BIN registra las acciones físicas realizadas y
también intenta construir una representación semántica de ellas.

La intención de Etapa 2 es que la demostración no sea considerada
simplemente una macro rígida.

La demostración funciona como evidencia del objetivo.

Qwen recibe información sobre lo que hizo el usuario y debe intentar
comprender qué resultado se buscaba.

Cuando la tarea vuelve a ejecutarse, Qwen puede observar la situación actual
y determinar el siguiente paso que debe realizar BIN.

El ciclo general del agente es:

OBSERVAR
↓
ANALIZAR
↓
ELEGIR UNA ACCIÓN
↓
EJECUTAR
↓
VOLVER A OBSERVAR
↓
CONTINUAR / FINALIZAR / REPORTAR ERROR

============================================================
TAREAS RETRASADAS — NUEVO EN V1.8
============================================================

BIN ahora puede detectar tareas cuya hora programada ya pasó.

Cuando existen tareas retrasadas, BIN muestra un popup con la lista de
ejecuciones pendientes.

Cada tarea tiene dos opciones:

✓ Ejecutar la tarea retrasada.

✕ Omitir esa ejecución.

Las tareas retrasadas aceptadas se ordenan cronológicamente según la hora
en la que originalmente debieron ejecutarse.

Sin embargo, BIN protege las tareas que todavía pueden ejecutarse a tiempo.

Ejemplo:

10:00 — Tarea A
10:20 — Tarea B
11:00 — Tarea C

Si A y B están retrasadas, BIN puede comenzar A.

Si después de terminar A faltan solamente unos minutos para las 11:00,
BIN no comenzará B.

El orden será:

Tarea A retrasada
↓
Tarea C programada a tiempo
↓
Tarea B retrasada

La prioridad general de V1.8 es:

1. Tareas que todavía pueden ejecutarse a tiempo.
2. Tareas retrasadas aprobadas por el usuario.
3. Entre las tareas retrasadas, primero la más antigua.

BIN también evalúa la duración conocida de una tarea retrasada para evitar
iniciarla cuando probablemente interfiera con una tarea programada próxima.


============================================================
RESET TAREA — NUEVO EN V1.8
============================================================

Cuando una ejecución se encuentra pausada aparece la opción:

RESET TAREA

Esta función permite abandonar completamente la ejecución actual sin
eliminar la automatización guardada.

RESET TAREA limpia:

- Progreso de la ejecución.
- Tiempo transcurrido.
- Acción actual.
- Repetición actual.
- Checkpoints temporales.
- Plan temporal generado por Qwen.
- Historial temporal del agente.
- Estado temporal del supervisor.
- Información de ejecución actual.
- Barra flotante de continuación.
- Panel de acciones asociado a esa ejecución.

RESET TAREA NO elimina:

- La tarea.
- Las acciones originales.
- Las acciones semánticas.
- El objetivo aprendido.
- La programación.
- La demostración original.

Su objetivo es permitir abandonar una ejecución problemática y dejar BIN
preparado para continuar trabajando normalmente.


============================================================
LIMPIAR PANEL DE ACCIÓN — NUEVO EN V1.8
============================================================

El Panel de acciones dispone ahora de:

LIMPIAR PANEL DE ACCIÓN

Esta función vacía únicamente el espacio de trabajo actual.

No elimina ni modifica las acciones almacenadas dentro de las tareas.

Después de limpiar el panel, el usuario puede proporcionar nuevas
instrucciones a Qwen sin mezclar las nuevas acciones con instrucciones
anteriores.

Esto convierte al Panel de acciones en un espacio de trabajo temporal
independiente de las automatizaciones guardadas.


============================================================
LIMITACIONES IMPORTANTES DE V1.8
============================================================

BIN todavía trabaja de manera relativamente lenta cuando Qwen necesita
analizar repetidamente la pantalla.

Por esta razón es posible que algunas tareas acumulen retrasos.

El sistema de reorganización incorporado en V1.8 permite manejar parte de
esta situación.

Sin embargo, el objetivo de futuras versiones será reducir significativamente
los tiempos de procesamiento.

La visión a 640 x 360 continúa siendo uno de los principales compromisos
entre:

PRECISIÓN VISUAL

y

VELOCIDAD DE PROCESAMIENTO

Por el momento se mantendrá esa resolución y se favorecerá el desarrollo de
herramientas complementarias.


============================================================
ESTRATEGIA OPERATIVA DE V1.8
============================================================

Durante el uso real de BIN V1.8 se utilizará una combinación de:

- Automatización visual mediante Qwen.
- Automatización determinista mediante Python.
- Funciones Win32.
- pynput.
- Comandos de Windows.
- Scripts complementarios.
- Software auxiliar.
- Comandos extraordinarios desarrollados por el usuario.
- Supervisión visual de BIN/Qwen.

La intención no es obligar a Qwen a resolver visualmente todas las
operaciones.

Si una tarea puede resolverse de forma más rápida y confiable mediante un
comando específico, BIN podrá utilizar ese comando y Qwen podrá comprobar
el contexto o el resultado.

Esto permitirá avanzar en automatizaciones reales mientras el núcleo del
agente continúa evolucionando.


============================================================
PENDIENTES POR MEJORAR
============================================================


1. NOTIFICACIONES DE ERROR MEDIANTE WHATSAPP
------------------------------------------------------------

En caso de error, estancamiento o imposibilidad de completar una tarea,
BIN debería poder informar automáticamente al usuario mediante WhatsApp.

Se deben evaluar al menos dos posibilidades:

A) Configurar un número de WhatsApp específico como destino de las
notificaciones.

B) Enseñar a Qwen/BIN a utilizar la aplicación de WhatsApp para encontrar
al usuario y enviar el mensaje.

El objetivo es que, antes de finalizar definitivamente una tarea por error,
BIN pueda informar:

- Qué tarea estaba realizando.
- En qué punto se produjo el problema.
- Qué intentó hacer.
- Qué error encontró.
- Si necesita intervención del usuario.


2. BITÁCORAS AUTOMÁTICAS DE TAREAS
------------------------------------------------------------

Agregar dentro de la lista de tareas un sistema de bitácoras automáticas.

Después de una ejecución, Qwen debería poder procesar lo ocurrido y generar
una conclusión sobre el resultado.

Ejemplo:

TAREA:
Organizar archivos.

RESULTADO:
Completada.

BITÁCORA:
BIN encontró 24 archivos, creó tres carpetas, clasificó correctamente
22 archivos y dejó 2 sin mover porque no pudo determinar su categoría.

La bitácora debe permitir entender qué ocurrió realmente y no limitarse a
mostrar simplemente:

COMPLETADA

o

ERROR.


3. DISEÑO DEL CHAT
------------------------------------------------------------

Modificar la presentación visual del chat.

Los mensajes deberán mostrarse de la siguiente manera:

Qwen / BIN:
lado izquierdo.

Usuario:
lado derecho.

Esto permitirá distinguir visualmente la conversación de una forma mucho
más natural.


4. QWEN DEBE CONOCER LA LISTA DE TAREAS
------------------------------------------------------------

Actualmente Qwen necesita mayor contexto sobre las automatizaciones
existentes.

En futuras versiones debería poder recibir y analizar la lista de tareas.

Desde el chat debería ser posible realizar solicitudes como:

"¿Qué tengo programado mañana?"

"Cambia la tarea de publicaciones de las 5:00 a las 6:30."

"No ejecutes esta tarea durante el fin de semana."

"Ejecuta primero esta tarea."

"¿Qué tarea está causando retrasos?"

Para permitir esto probablemente será necesario ampliar la estructura de:

data/tareas.json

incorporando nuevos parámetros y metadatos que hagan más robusta cada
automatización.

Qwen deberá poder consultar esta información y BIN deberá proporcionar
herramientas controladas para modificarla de manera segura.


5. BOTÓN FLOTANTE PARA DETENER ACCIONES DEL CHAT
------------------------------------------------------------

Cuando el usuario solicita una acción mediante el chat y Qwen comienza a
operar Windows, debe aparecer un botón flotante:

PARAR ACCIÓN

Este botón permitirá detener inmediatamente el objetivo solicitado desde
el chat.

El objetivo es no depender de regresar a la ventana principal de BIN para
cancelar una acción.


6. SISTEMA MECÁNICO DE IDIOMAS
------------------------------------------------------------

Evaluar la incorporación de un selector de idioma.

El objetivo es evitar que Qwen tenga que dedicar capacidad de procesamiento
a interpretar constantemente cambios de idioma.

Ejemplo para español:

Usuario escribe en español.
↓
BIN traduce mecánicamente la instrucción al idioma óptimo utilizado
internamente por Qwen.
↓
Qwen procesa la solicitud.
↓
BIN traduce mecánicamente la respuesta al español.
↓
Usuario recibe la respuesta en español.

El código generado por Qwen NO deberá traducirse automáticamente.

También deberán mantenerse sin modificación elementos donde una traducción
pueda provocar errores, como:

- Código.
- Rutas.
- Comandos.
- Nombres de archivos.
- Parámetros.
- JSON.
- Identificadores técnicos.

La finalidad principal será disminuir tiempos de procesamiento y mantener
mayor consistencia en las instrucciones internas del modelo.


7. REDUCIR TIEMPOS DE PROCESAMIENTO
------------------------------------------------------------

Evaluar diferentes estrategias para disminuir el tiempo que Qwen necesita
para responder y tomar decisiones.

Áreas a investigar:

- Reducir el tamaño de los prompts.
- Reducir información repetida enviada en cada iteración.
- Optimizar el historial entregado a Qwen.
- Enviar solamente contexto relevante.
- Mejorar el uso de memoria de tareas.
- Evitar capturas cuando no sean necesarias.
- Utilizar comprobaciones deterministas antes de consultar a Qwen.
- Desarrollar más comandos especializados.
- Evaluar diferentes resoluciones según el tipo de tarea.
- Utilizar visión de mayor resolución solamente cuando sea estrictamente
  necesario.
- Reducir consultas innecesarias al modelo.
- Evaluar modelos locales más rápidos cuando existan alternativas
  suficientemente capaces.
- Separar tareas simples de tareas que realmente necesitan razonamiento
  visual.


============================================================
OBJETIVO DE LAS SIGUIENTES VERSIONES
============================================================

BIN debe evolucionar progresivamente desde un automatizador asistido por IA
hacia un agente local capaz de:

ENTENDER QUÉ QUIERE EL USUARIO.

OBSERVAR EL ESTADO ACTUAL DEL PC.

ELEGIR LA HERRAMIENTA ADECUADA.

REALIZAR LA ACCIÓN.

COMPROBAR EL RESULTADO.

ADAPTARSE CUANDO EL ENTORNO CAMBIA.

INFORMAR CUANDO NO PUEDE CONTINUAR.

APRENDER CONTEXTO ÚTIL SOBRE LAS AUTOMATIZACIONES EXISTENTES.

Todo esto sin convertir cada operación del PC en una inferencia visual
costosa.

La dirección del proyecto continúa siendo una arquitectura híbrida:

QWEN
Comprende, interpreta, analiza y decide.

BIN
Ejecuta, controla, programa, registra y protege el sistema.

HERRAMIENTAS ESPECIALIZADAS
Resuelven operaciones concretas de forma rápida y determinista.

ESTADO DE V1.8
============================================================

BIN V1.8 se considera:

VERSIÓN OPERATIVA PARA USO REAL Y PRUEBAS.

VERSIÓN FINAL DEL AGENTE.

A partir de esta versión, el objetivo principal es comenzar a utilizar BIN
en automatizaciones reales, observar sus limitaciones en condiciones
cotidianas y utilizar esa experiencia para decidir qué mejoras ofrecen el
mayor impacto en las siguientes versiones.
